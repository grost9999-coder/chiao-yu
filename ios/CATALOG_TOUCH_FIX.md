# Catalog modal and industry templates

The catalog dialog now uses the native HTML dialog top layer rather than a fixed overlay inside the app's clipped container. Stationary touch-end activation is deduplicated against synthetic clicks, while scrolling gestures, keyboard activation and mouse clicks retain their separate behavior. Cancel/Close do not save. The footer remains visible as content scrolls, the editor scrolls into view, invalid input shows an alert, and the main Save includes a valid unfinished item draft. Storage errors still leave the dialog open. Existing historical entries and calculation logic are unchanged.

There are 20 business templates plus Custom, separately from the 20 independent vendor accounts: food/snacks, beverages/coffee/desserts, produce/fresh food, clothing/accessories, goods/crafts, services/repairs, fried chicken, breakfast, noodles/braised food, barbecue, bento, bakery, fruit, seafood, meat/frozen food, flowers/plants, toys/stationery, cosmetics/skincare, phone accessories/repairs, and pet food/supplies. Applying a template appends selectable items with zero unit prices, without creating accounts, costs or physical inventory. Existing custom items are retained.

The actual packaged iOS Web/index.html is exercised by `ios/tests/catalog-browser.cjs` in mobile WebKit. Coverage includes Cancel, Close, touch on template and new-item buttons, all four item types, direct draft saving, validation errors, reload persistence, vendor isolation, and saving all 20 templates. Browser testing supplements pure catalog unit tests; physical TestFlight testing remains necessary, especially on the user's iOS version. Native StoreKit access and deployment are unchanged.

## Root cause of the unresponsive Cancel/Close/Save buttons

The catalog dialog and the main content `<div key={vendorId}>` were siblings that shared the same React key (the vendor id). React builds a key→fiber map when reconciling siblings, so the duplicate key made it lose the dialog's deletion record: closing set `catalogOpen=false` and the component left the React tree, but the `<dialog>` DOM node was never removed or closed. Template/add buttons kept working because they only update state inside the dialog. The dialog now has its own unique key (`"catalog:"+vendorId`). `catalog-browser.cjs` covers Cancel, Close and Save closing the dialog.
